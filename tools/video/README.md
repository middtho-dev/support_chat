# Видео Telegram

Независимый сервис загрузки публичных видео YouTube (включая Shorts) и Instagram.
Управление: Workspace → Видео. Авторизация общая с Workspace и Mini App.

## Подключение

1. Основной бот Workspace подключается автоматически. В BotFather Mini App включите у него **Guest Mode**.
2. В разделе «Видео → Подключение» проверьте бота и включите обработку. Повторно вводить токен не нужно.
3. В другом чате напишите `@имя_бота ссылка` или ответьте на сообщение со ссылкой, указав `@имя_бота`.
4. В личном чате основного бота используйте `/video ссылка` или `/video` в ответ на ссылку. Обычные сообщения и ссылки остаются в поддержке.

Сразу после приёма создаётся Rich Message со статусом. Загрузчик сообщает этапы и реальные проценты скачивания; изменения объединяются и отправляются не чаще раза в 1,2 секунды, с учётом Telegram retry_after. Готовое видео заменяет статус через editMessageMedia. В Guest Mode используется один answerGuestQuery и полученный inline_message_id; повторного ответа нет. Ошибка отображается в том же сообщении. Бот не получает историю чата. Общий бот обрабатывает только явный вызов видео; сообщения поддержки не перехватываются. Для получения таких сообщений должны быть разрешены соответствующие обновления Telegram.

Переключатель «Удалять сообщение-вызов» включён по умолчанию. Удаляется только сам вызов после подтверждения статуса, а не сообщение, на которое ответили. В личном чате с ботом это доступно; в группах нужны права удаления. Guest Mode не даёт права удалять чужие сообщения, поэтому гостевой вызов остаётся. Неопределённый результат создания ответа после сетевого сбоя или перезапуска не повторяется автоматически.

## Развёртывание

Скопируйте `.env.example` в `.env`. Сгенерируйте три независимых секрета: `openssl rand -hex 32`. `VIDEO_ENCRYPTION_KEY` должен содержать ровно 64 hex-символа. Значение `VIDEO_SERVICE_TOKEN` также добавьте в корневой `.env`; `VIDEO_SERVICE_URL=http://127.0.0.1:7800` задаёт адрес прокси Workspace.

В корневом `.env` включите `VIDEO_SHARED_BOT=1`. В `tools/video/.env` задайте `VIDEO_MAIN_BOT_TOKEN` из существующего `TELEGRAM_BOT_TOKEN` на сервере; не передавайте его через браузер и не коммитьте. Только поддержка регистрирует общий Telegram webhook. Она сохраняет видео-вызовы в отдельной очереди и передаёт их внутреннему `/api/video/update` с сервисной авторизацией. При остановке загрузчика обращения продолжают обрабатываться; его очередь повторяет передачу. Гостевые события включены в allowed_updates.

В Caddy, **перед** общим reverse_proxy, оставьте:

```caddy
reverse_proxy /api/video/files/* 127.0.0.1:7800
```

`docker compose -f tools/video/compose.yml up -d --build`. Пересоберите Workspace после добавления настроек прокси. Порт 7800 должен быть свободен и исключён из выдачи FRP. Не публикуйте административный API напрямую.

## Ограничения

- Не более 20 ожидающих заданий, один загрузчик; по умолчанию 10 вызовов пользователя в час, 45 МБ, 180 секунд, 720p. Превышающие лимиты вызовы игнорируются.
- Файлы выдаются по случайной временной ссылке; срок по умолчанию 30 минут. Журнал — последние 30 заданий за сутки. После перезапуска незавершённая отправка не повторяется, чтобы не дублировать сообщения.
- Закрытые/платные публикации и требующие входа ссылки не поддерживаются. Источник может блокировать IP или требовать авторизацию. Успешный webhook сам по себе не подтверждает возможность скачать конкретное видео.
- Токен зашифрован в хранилище. Смена бота разрешена только при пустой очереди. Чужой webhook не перезаписывается автоматически.
- Для проверки отправки нужен подключённый основной бот; тесты используют подменённые API и не отправляют сообщения пользователям.

Документация: https://core.telegram.org/bots/features#guest-bots и https://github.com/yt-dlp/yt-dlp.

Без VIDEO_MAIN_BOT_TOKEN сервис сохраняет совместимость с отдельным ботом и собственным webhook. В таком варианте VIDEO_SHARED_BOT в Workspace должен быть выключен.

## Автоматическое уменьшение

Если ролик не помещается в выбранный лимит, загрузчик пробует более низкое разрешение (до 240p). Если готового варианта нет, он скачивает ограниченный по размеру исходник и перекодирует его в H.264/AAC, постепенно снижая битрейт и разрешение. Статус показывает этап и ход сжатия. Перед отправкой проверяются размер, полная длительность и сохранение звука; файл не обрезается по количеству байтов. Маленькие файлы не перекодируются.

Для защиты диска промежуточный исходник ограничен 192 МБ на поток, либо меньшим бюджетом по свободному месту. Каждая загрузка ограничена 90 секундами, попытка сжатия — 180 секундами; используется один поток кодирования. Лимит длительности по-прежнему действует. Ошибки доступа к источнику не маскируются повторными попытками уменьшения.
