# Голосовые Telegram → текст OpenAI

Независимый проект `tools/voice`, отдельный процесс и Docker volume. Управление:
панель `/admin?view=voice`, пункт «Аудио» в Workspace. В Mini App используется
та же авторизация; доступ к модулю — только с правом управления настройками.

## Подключение владельцем

1. Создайте **отдельного** бота в [@BotFather](https://t.me/BotFather).
   Включите Business / Secretary Mode. Название пункта зависит от версии клиента.
   Не используйте токен бота поддержки: два потребителя getUpdates конфликтуют.
2. Получите ключ проекта [OpenAI API](https://platform.openai.com/api-keys),
   настройте биллинг и лимит расходов проекта. Подписка ChatGPT не заменяет API.
3. В разделе «Аудио» сохраните токен бота, OpenAI API key и числовой Telegram ID
   владельца Premium/Business-аккаунта. Для нескольких владельцев — через запятую.
   Пустые поля ключей сохраняют текущие значения; ключи назад в браузер не отдаются.
4. В Telegram аккаунта: Настройки → Telegram Business → Чат-боты (Connected Bots).
   Подключите созданного бота, выберите доступные чаты и разрешите ответы.
   Если хотите удалять исходные голосовые — разрешите удаление всех сообщений.
   Если пункта нет, обновите официальный Telegram и проверьте доступность Business
   в аккаунте. Бот не входит в аккаунт по паролю или коду и не читает произвольные чаты.
5. Нажмите «Проверить бота». Business должен быть включён, webhook — отсутствовать.
   Если webhook установлен другим сервисом, отключите его там или создайте другого бота.
6. Выберите входящие/исходящие, типы аудио, разрешённые и исключённые ID чатов.
   Исключения имеют приоритет. Сохраните настройки, нажмите «Включить» и отправьте
   новое голосовое в доступный чат. ID чата будет виден в журнале заданий.

Список подключений обновится после включения polling. Telegram разрешает ответы
от имени аккаунта в подходящих личных чатах с входящими сообщениями за последние
24 часа; исходящее сообщение само по себе это окно не открывает.

## Настройки и ограничения

- Голосовые, видеокружки и аудиофайлы; остальные вложения не обрабатываются.
- Минимальная/максимальная длительность, дневной лимит суммарных минут по UTC.
  Лимит резервируется при постановке в очередь, включая неуспешные попытки;
  это ограничение объёма, а не точная оценка стоимости OpenAI.
- Язык авто/ISO-код, произвольные названия моделей; по умолчанию
  `gpt-4o-mini-transcribe` и `gpt-4.1-mini`.
- Оформление включается отдельно: читабельно, близко к оригиналу или кратко;
  эмодзи и дополнительные пожелания редактора. Без оформления отправляется
  результат распознавания. Качество и точность фактов требуют проверки человеком.
- Подпись перед текстом, тихая отправка, сохранение или удаление оригинала.
  Текст отправляется **в тот же чат**, его увидит собеседник. Удаление происходит
  только после подтверждения отправки всех частей; без прав оригинал сохраняется.
- Файл до 20 МБ (Telegram getFile); до 1200 секунд. ffmpeg преобразует его в MP3.
  Более длинные записи пропускаются. Старые и отредактированные сообщения
  не транскрибируются; обрабатываются новые business_message после включения.
- Очередь до 200 активных заданий. Повторные update_id/message_id не создают дублей.
  Транскрибация и очистка повторяются до трёх раз; неоднозначная отправка требует
  проверки чата, автоматический повтор отключён. Бот не обещает exactly-once
  доставку при аварии между подтверждением Telegram и записью на диск.
- При отключении текущий HTTP-запрос может завершиться, следующие отправки
  прекращаются. Перед изменением настроек остановите бота; текущая обработка
  должна завершиться. Незавершённые задания сохраняются для продолжения.

## Данные

Аудио и текст передаются в OpenAI; для Responses задано `store: false`.
Это не отменяет применимые правила хранения данных провайдером.
Аудиофайлы удаляются с локального диска после обработки. Текст задания хранится
локально 1–168 часов (по умолчанию 24); незавершённые задания сохраняются до
завершения. Удаление устаревших завершённых заданий выполняется во время работы.
Токены шифруются AES-256-GCM. Сохраните VOICE_ENCRYPTION_KEY отдельно от volume:
без него восстановить секреты нельзя. Резервные копии чата не включают этот volume.

## Развёртывание

Скопировать `.env.example` в `.env` рядом с compose.yml. Сгенерировать два разных
случайных секрета (например, `openssl rand -hex 32`): VOICE_SERVICE_TOKEN и
VOICE_ENCRYPTION_KEY. Запустить `docker compose up -d --build` в tools/voice.
API слушает только 127.0.0.1:7500 (VOICE_PORT меняется через окружение).
В корневом `.env`: VOICE_SERVICE_URL=http://127.0.0.1:7500 и такой же
VOICE_SERVICE_TOKEN. Перезапустить только support-chat. Порт сервиса должен
быть исключён из разрешённых FRP-портов и закрыт снаружи.

Локально нужен Node.js 20 и ffmpeg в PATH (или FFMPEG_PATH). Запуск `npm start`;
переменные окружения должны быть заданы перед запуском. Единственный экземпляр
воркера на volume, без масштабирования. Проверки: `npm run check`, `npm test`.

Источники: [Telegram Business bots](https://core.telegram.org/bots/features#business-bots),
[права и удаление](https://core.telegram.org/bots/api#deletebusinessmessages),
[транскрибация OpenAI](https://developers.openai.com/api/docs/guides/speech-to-text),
[Responses API](https://developers.openai.com/api/docs/guides/text).

## VLESS для запросов из аудиомодуля

В «Аудио» остановите бота, вставьте ссылку `vless://` в блок «VPN-соединение»,
включите «Использовать VLESS для OpenAI» и сохраните настройки. Затем нажмите
«Проверить VPN». Проверка обращается к OpenAI без API-ключа и без платного запроса.
Статус «Клиент VPN запущен» означает готовность локального Xray, а проверка
подтверждает доступность OpenAI через удалённый сервер.

Отдельный переключатель направляет через VPN также Telegram API и загрузку аудио.
VPN применяется только к этому аудиоботу. Поддержка, FRP и системные маршруты
не переключаются. При сбое VPN прямого обходного соединения нет. Чтобы вернуться
к прямому соединению, выключите переключатель VPN и сохраните настройки.

Поддерживаются TCP/RAW, WebSocket, gRPC, XHTTP, HTTPUpgrade с TLS и допустимые
сочетания REALITY; XTLS Vision — для TCP. Неподдерживаемые параметры отклоняются,
а не игнорируются. Нужна ссылка отдельного профиля, не URL подписки. Проверка
сертификатов не отключается. Пустое поле сохраняет прежнюю ссылку; она шифруется
тем же ключом, что токены, и не возвращается в браузер. VPN по умолчанию выключен.

Docker устанавливает Xray 26.3.27 из официального релиза с проверкой SHA-256
(amd64/arm64). Локально дополнительно выполните `npm ci` и установите Xray в PATH
или задайте `XRAY_PATH`. Внутренний прокси слушает только `127.0.0.1:7501`, защищён
случайным паролем и допускает только OpenAI/Telegram HTTPS. Порт меняется через
`VOICE_PROXY_PORT`; исключите его из FRP. Конфигурация Xray временная, доступна
только пользователю сервиса и удаляется при остановке клиента.

Описание протокола: [Project X](https://xtls.github.io/en/config/outbounds/vless.html).

## Скорость и выбор моделей

Очередь обрабатывается независимо от Telegram long polling: следующие задания
не ждут пустого ответа getUpdates. Одновременно распознаётся одно сообщение,
чтобы сохранить порядок ответов и ограничить нагрузку.

В панели доступны GPT-Transcribe, GPT-4o Mini Transcribe, GPT-4o Transcribe
и Whisper для распознавания; GPT-5.4 Nano / Mini, GPT-4.1 Mini, GPT-4o Mini
и GPT-4.1 для оформления. «Другая модель» позволяет указать свой ID.
Доступ зависит от API-ключа. Для GPT-5.4 Mini / Nano дополнительное рассуждение
по умолчанию выключено (`none`); можно выбрать `low` или `medium`.
Более высокий уровень может увеличивать задержку. Новая модель не гарантирует
ускорение каждого запроса: сравнивайте время на своих примерах.

Набор «Быстро · без оформления» выбирает Mini Transcribe и убирает второй запрос
OpenAI. «Быстро + эмодзи» добавляет GPT-5.4 Nano, «Аккуратное оформление» —
GPT-5.4 Mini. Наборы только заполняют поля: перед сохранением остановите бота.
Остановка не сбрасывает введённые поля. Обычное обновление статуса тоже их сохраняет.

Настройки разделены на вкладки «Текст и модели», «Сообщения», «Подключение»
и «Журнал». Редактирование и эмодзи включаются независимо. Отдельно регулируются
пунктуация, слова-паразиты, повторы, абзацы, списки, манера речи, смягчение грубой
лексики, степень сокращения и лимит ответа. Выключенные правки явно запрещены
в инструкции модели; генерация всё равно требует проверки на своих примерах.
Для распознавания можно задать язык и словарь имён/терминов.

У эмодзи три варианта размещения: внутри текста рядом со смыслом (по умолчанию),
в начале абзацев или только в конце; три уровня количества. Пользовательские
пожелания не должны отменять выключенные функции.

«Попробовать на примере» проверяет текущие несохранённые настройки оформления
на тексте до 3000 символов. Пример передаётся OpenAI и оплачивается как обычный
API-запрос; результат показывается только в панели, без отправки в Telegram.
При выключенных редактировании и эмодзи возвращается исходный текст без запроса.
Проверка не меняет настройки, задания, ключи или правила удаления.

Во вкладке «Сообщения» шесть независимых переключателей удаления оригиналов:
входящие/исходящие × голосовые/видеокружки/аудиофайлы. Удаление происходит только
после подтверждения отправки всех частей расшифровки и при наличии права Telegram.
Обновление сохраняет прежнее поведение: старое `deleteOriginal=false` переводится
в шесть выключенных переключателей, `true` — во включённые. Существующие новые
переключатели не перезаписываются. Старые API-клиенты ещё могут передавать
`deleteOriginal`, если в запросе нет отдельных переключателей.

В новых заданиях отображаются этап и измеренные времена: очередь, аудио
(загрузка, преобразование и распознавание), оформление, отправка и общее время
с постановки в очередь. Повторные попытки суммируются; общее время включает
ожидание повторов. Это измерения конкретного запроса, не обещание фиксированной
скорости модели. Сеть, VPN, длина записи и загрузка OpenAI влияют на результат.
Ошибки баланса, ключа и доступа не повторяются автоматически; временные лимиты
и сетевые ошибки продолжают использовать ограниченные повторы.
