# FRP — самостоятельный инструмент мультитула

## Единая админка и Telegram Mini App

Основной вход теперь через **«Устройства» (FRP)** в админке чата. Раздел открывается на том же домене, использует текущую сессию администратора/Telegram и не запрашивает отдельный ключ. Доступен администраторам с правом управления настройками; права перепроверяются на каждом API-запросе. Старый `/admin/frp` открывает `/admin?view=frp` на том же сайте.

Чат подключается к отдельному процессу FRP через серверный API: `FRP_SERVICE_URL` (по умолчанию `http://127.0.0.1:7400`) и `FRP_SERVICE_TOKEN` в корневом `.env`. Значение ключа должно совпадать с `FRP_ADMIN_TOKEN` в `tools/frp/.env`; оно не передаётся в браузер. После изменения окружения пересоздайте контейнер чата. Установщик `setup-https.sh` связывает окружение автоматически и пересобирает чат, если найден корневой `.env`. Отдельная FRP-панель остаётся резервным входом, но переходить в неё больше не требуется. `FRP_PANEL_URL` больше не используется.

Имена клиентов и туннелей кликабельны. Для клиента выбирается активный LuCI/Web-туннель, для SSH — `ssh://` (нужен установленный SSH-обработчик). Ссылки строятся из сохранённого домена и remotePort. LuCI на локальном порту 80 открывается по **HTTP**, например `http://router.kv9.ru:8017/`: FRP не добавляет TLS к TCP-туннелю. Для туннелей с HTTPS в имени используется HTTPS. В Mini App веб-ссылки открываются через Telegram.openLink. Сам раздел управления остаётся внутри Mini App.

## Изменяемые настройки

Для существующих `frpc.toml` без `auth.token` выберите в панели режим **«Существующие конфиги: без токена, TLS необязателен»**, сохраните при остановленном FRP и включите сервер. Клиентские конфиги менять не нужно: поддерживаются обычные `serverAddr`, `serverPort` и блоки `[[proxies]]`, в том числе `Home_Luci` на 8021 и `Home_SSH` на 2221. TLS-клиенты также поддерживаются. В этом режиме любой клиент, знающий адрес, может регистрировать туннели на разрешённых портах. Авторизация веб-панели остаётся обязательной. Обратное переключение возвращает сохранённый токен и обязательный TLS.

В панели можно сохранить домен/IP устройств (по умолчанию `router.kv9.ru`), порт подключения, IP прослушивания FRP, начало/конец диапазона туннелей, исключённые порты, новый токен устройств, интервал обновления и лимит истории. Настройки доступны и при работающем FRP. Сохранение кратко перезапускает сервер; при ошибке запуска восстанавливается предыдущая конфигурация. Новые значения автоматически используются в подсказках, примере frpc.toml и конфигурации frps. Смена домена не настраивает DNS; смена токена требует обновления клиентов.

Начальные значения перечислены в `.env.example` (`FRP_SERVER_HOST`, `FRP_SERVER_PORT`, `FRP_BIND_ADDR`, `FRP_PORT_START`, `FRP_PORT_END`, `FRP_RESERVED_PORTS`, `FRP_REFRESH_SECONDS`, `FRP_HISTORY_LIMIT`). После первого запуска приоритет имеют сохранённые настройки панели. Старое значение `routers.kv9.ru` из первой версии исправляется однократно; другие пользовательские домены не перезаписываются.

Параметры самого приложения меняются через окружение и перезапуск FRP-панели: `FRP_PANEL_HOST`, `FRP_PANEL_PORT`, `FRP_ADMIN_TOKEN`, `FRP_DIR`. Docker healthcheck учитывает порт; при привязке к конкретному IP задайте также `FRP_PANEL_HEALTH_HOST`.


Чат в корне репозитория и `tools/frp` — **два независимых приложения**. У FRP отдельные процесс, Docker Compose, секрет входа и том данных. Он не импортирует код чата, не использует SQLite/Telegram и не требует установки зависимостей чата. Команды `setup.sh`/`update.sh` в корне относятся только к чату.

## Запуск на Linux с Docker

### Установка с HTTPS на сервере чата

На сервере с уже установленными Docker и Caddy выполните из корня репозитория:

```sh
git pull --ff-only
sudo bash tools/frp/setup-https.sh router.kv9.ru
```

Скрипт создаёт отдельный `.env` с ключом панели, если файла ещё нет, запускает FRP Compose и подключает общую админку чата, проверяет локальную панель, добавляет отдельный сайт в существующий Caddy и включает автоматическое получение HTTPS-сертификата. Ключ входа — `FRP_ADMIN_TOKEN` в `tools/frp/.env`. Если `.env` уже скопирован из примера, замените заглушку ключа перед запуском. Повторный запуск сохраняет секрет и данные. Домен можно передать другим аргументом; порт берётся из `.env`.

DNS домена должен указывать на этот сервер, входящие 80/443 должны доходить до Caddy. Для клиентов FRP отдельно используется TCP 7000. HTTPS-панель не слушает порт 7000. Скрипт проверяет результат по HTTPS и сообщает об ошибке, если сертификат получить не удалось. При ошибке проверки конфигурации или reload восстанавливается прежний Caddyfile. Последующие обновления чата сохраняют импорт сайта FRP.

`ERR_SSL_PROTOCOL_ERROR` означает сбой TLS до загрузки панели. Простое изменение адреса не выпускает сертификат: нужен HTTPS reverse proxy, который настраивает команда выше. Для диагностики на сервере:

```sh
curl -f http://127.0.0.1:7400/health  # используйте свой FRP_PANEL_PORT
sudo caddy validate --config /etc/caddy/Caddyfile
sudo journalctl -u caddy --no-pager -n 50
```

### Ручной запуск (без настройки HTTPS)

```sh
cd tools/frp
cp .env.example .env
# Задайте FRP_ADMIN_TOKEN: случайный секрет длиной не менее 24 символов.
docker compose up -d --build
```

Панель слушает `127.0.0.1:7400`. Опубликуйте её через существующий HTTPS reverse proxy **отдельным виртуальным хостом**, направленным на этот адрес. Можно использовать `router.kv9.ru` для HTTPS панели и тот же домен с TCP-портом 7000 для устройств. Для локальной проверки без proxy откройте `http://127.0.0.1:7400`.

Вход: отдельный `FRP_ADMIN_TOKEN` из `.env`. Ключ хранится в памяти страницы до выхода/перезагрузки. Токен подключения устройств генерируется автоматически и отличается от ключа панели.

Нажмите **Установить FRP**, затем **Включить**. Приложение скачивает последний стабильный официальный релиз с GitHub для своей ОС/архитектуры, проверяет SHA-256 из GitHub release metadata, извлекает только frps и создаёт TOML. Для установки нужны исходящий HTTPS к GitHub и `tar` (есть в образе). Поддерживаются x64 и arm64. Обновление выполняется той же кнопкой при остановленном FRP.

## Подключение устройств

- По умолчанию: `router.kv9.ru:7000`. Домен должен указывать на публичный IP машины с FRP; DNS-проксирование HTTP для подключения frpc не подходит.
- По умолчанию разрешены TCP/UDP-порты 1000–65535 за исключением порта подключения, внутреннего dashboard, панели, Caddy admin (2019), чата (3000,3001 и FRP_CHAT_PORT) и дополнительных исключений. Диапазон и исключения меняются в панели.
- В firewall разрешите TCP 7000 и конкретные TCP/UDP-порты сервисов. Панель не изменяет firewall или DNS автоматически.
- В панели раскройте пример `frpc.toml`, скопируйте на устройство, задайте уникальное имя, localPort и свободный remotePort. Запустите frpc на устройстве.
- FRP API автоматически сообщает о клиентах: панель показывает имя/ID, IP, состояние и связанные TCP/UDP-порты. Устройства видны даже без туннелей. Идентичность определяется клиентом FRP, а не аппаратным MAC; старые клиенты без стабильного clientID могут создавать новые записи после переподключения.
- Ниже отображаются все TCP/UDP-туннели отдельными строками; рекомендуем имена `router-01-ssh`, `router-01-web`. Неактивные клиенты и туннели остаются в истории (по умолчанию до 10 000 записей каждого вида), включая после перезапуска. «Онлайн» означает регистрацию в FRP, а не проверку доступности локального сервиса.
- По умолчанию состояние обновляется каждые 5 секунд; интервал и лимит истории меняются в панели. При сбое API состояние отмечается как неизвестное.

## Независимое управление

```sh
# Из tools/frp: эти команды никак не управляют чатом
docker compose stop
docker compose up -d --build
docker compose logs --tail=100
```

FRP запускается автоматически вместе со своей панелью, если раньше был включён. Кнопка «Выключить» сохраняет выключенное состояние. При аварийном завершении frps панель показывает ошибку, повторный запуск — кнопкой «Включить». Данные и бинарный файл находятся в отдельном томе `frp-data`; не удаляйте его при обновлении.

Без Docker: Node.js 20+, `FRP_ADMIN_TOKEN` в окружении, затем `node tools/frp/server.js`. `.env` при таком запуске не подгружается автоматически; используйте `node --env-file=tools/frp/.env tools/frp/server.js`. Данные по умолчанию в `tools/frp/data`, путь меняется через `FRP_DIR`. Веб-порт: `FRP_PANEL_PORT`, адрес: `FRP_PANEL_HOST`. FRP требует отдельного supervisor для запуска панели после перезагрузки машины (например systemd).

Конфигурация и секреты записываются вне публичного каталога с ограниченными правами. Внутренний dashboard FRP использует случайный пароль и слушает только loopback. Панель должна быть доступна по HTTPS при удалённом использовании.

Проверка: `npm run check` и `npm test` из `tools/frp`.

### Linux и порты 1000–1023

FRP работает непривилегированным пользователем. На Linux с `net.ipv4.ip_unprivileged_port_start=1024` порты 1000–1023 потребуют изменения системного порога до 1000 (либо отдельной настройки capability для frps). При host networking это настройка хоста. Проверяйте `sysctl net.ipv4.ip_unprivileged_port_start`; изменения системного порога действуют для всех непривилегированных процессов хоста. Firewall настраивается отдельно от allowPorts FRP; разрешайте только диапазоны из allowedRanges, исключая служебные порты.


## Установщик роутеров OpenWrt

Внизу FRP находится генератор `.bat` для Windows 10/11. Укажите IP роутера,
пароль root и при необходимости порт SSH. Свободный внешний порт выбирается
из 20000–23000 с учётом разрешённых диапазонов, служебных портов, истории
устройств и ранее выданных файлов. При генерации порт проверяется повторно
и резервируется; пароль не записывается в состояние сервиса.

Файл запускается на компьютере в сети роутера с доступом в интернет.
Он загружает PuTTY Plink 0.85 с официального сайта, проверяет подпись
Simon Tatham и при первом SSH-подключении просит проверить ключ роутера.
FRPC и luci-app-frpc устанавливаются из настроенных репозиториев OpenWrt
через `apk` либо `opkg`. Отсутствие пакета или ошибка репозитория останавливают
установку; проверки подписей пакетов не отключаются.

Используется штатный `/etc/config/frpc`, доступный для редактирования через
LuCI. Добавляется `kv9_luci_<порт>`: TCP, 127.0.0.1:80. На свежей установке
удаляется демонстрационный SSH-туннель. Другие существующие туннели сохраняются;
при другом сервере в существующем конфиге установка останавливается, чтобы
не перенаправить их без ведома владельца. До изменения сохраняется копия
`/etc/config/frpc.kv9-backup-*`; при ошибке запуска конфигурация восстанавливается.
Запуск процесса не гарантирует регистрацию туннеля: проверьте статус в панели.

Файл содержит SSH-пароль и, в защищённом режиме, токен FRP. Передавайте его
только владельцу роутера и удаляйте после установки. Ссылка на скачивание
действует в текущем сеансе; после выхода для повторной генерации неиспользованный
порт можно освободить в списке выданных файлов. Старые файлы освобождённых портов
использовать нельзя. Порты известных устройств сохраняются занятыми даже после
сокращения истории. Неподконтрольные панели клиенты могут занять порт позднее;
при конфликте FRPS отклоняет второй туннель.

В Telegram WebView скачивание BAT зависит от клиента Telegram; если оно
не поддерживается, откройте ту же панель в обычном браузере на компьютере.
