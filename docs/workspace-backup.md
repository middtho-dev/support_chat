# Резервирование Workspace

`bash scripts/install-workspace-backup.sh` создаёт ежедневный systemd timer
`kv9ru-workspace-backup.timer` (02:30 UTC, случайная задержка до 15 минут).
`setup.sh` и `update.sh` устанавливают его перед запуском приложения.
Проверка: `systemctl list-timers kv9ru-workspace-backup.timer`.

Ручной проверенный снимок: `python3 scripts/workspace-backup.py snapshot`.
Повторная проверка: `python3 scripts/workspace-backup.py verify`.
Состояние и давность видны в Workspace → Система → Состояние.
Непроверенная копия и копия старше 36 часов требуют внимания.

Снимки находятся в `/var/backups/kv9ru-workspace`, доступны только root.
Хранятся семь последних снимков; объекты одинакового содержимого не дублируются.
Базы SQLite копируются через online backup и проверяются `quick_check`;
каждый объект проверяется SHA-256. Снимок публикуется только после проверки.

Включены постоянные Docker volumes поддержки (БД и вложения), FRP, Voice,
Video и Firmware, `.env` всех пяти приложений, существующие конфигурация и
база Lampac, правила доступа TorrServer, Caddyfile и unit Lampac. Манифест
содержит идентификаторы образов. Образы и системные пакеты восстанавливаются
отдельно из Docker registry / исходников; SSH-ключи в снимок не включаются.
Временные каталоги `files`, `tmp`, `cache`, `workspace-cache`, WAL/SHM и
символические ссылки исключены. Обработанное аудио/видео и кеш прошивок могут
потребовать повторной загрузки. Это согласованные снимки каждой SQLite-базы,
но не атомарный снимок всех сервисов в одну наносекунду.

## Проверка восстановления

```
python3 scripts/workspace-backup.py restore --restore-to /tmp/kv9ru-restore-check
```

Цель должна быть пустой отдельной папкой. Утилита запрещает восстановление
непосредственно в рабочий репозиторий, Docker volumes и системные каталоги.
После проверки root переносит нужные компоненты в их исходные места при
остановленном соответствующем сервисе, восстанавливает владельцев volumes (uid/gid и mode указаны в манифесте) и запускает
одного владельца Telegram polling. Не запускайте копии ботов с рабочими ключами.
Не восстанавливайте `.env` в общедоступное место; все файлы снимка закрыты.
Для disaster recovery сохраните отдельно доступ к GitHub и инструкции DEPLOY.md.

Локальная копия не защищает от потери VPS. Внешнее хранилище не настроено:
требуется выбранное владельцем место вне этого сервера. Не добавляйте
произвольный адрес или секрет в репозиторий. Каталог копий содержит секреты,
для передачи требуется защищённое хранилище и шифрованный канал.
