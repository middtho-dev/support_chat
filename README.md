# Support Chat

Веб-чат поддержки с операторской консолью в личном чате с Telegram-ботом.
По умолчанию на каждое открытое обращение приходится одна Rich-карточка
с диалогом и действиями. Группы и отдельные темы не нужны.

## Возможности

- обмен сообщениями в реальном времени через Socket.IO;
- фото и скриншоты, включая HEIC/HEIF, AVIF, DNG и TIFF с iPhone,
  видео, аудио и документы до 50 МБ;
- одна Rich-карточка обращения в общем чате каждого оператора;
- тикеты клиентов через личный чат с тем же ботом, без перехода на сайт;
- очередь тикетов и атомарная кнопка «Взять тикет» для нескольких операторов;
- Rich-карточки со статусом, каналом, Telegram-профилем и кнопками действий;
- Mini App с прямым открытием выбранного тикета;
- защита от дублей, очередь повторной доставки и контроль ошибок;
- уведомления о новых сообщениях, повторные напоминания и очистка после закрытия;
- автозакрытие тикета и HTTPS через Caddy.

## Подготовка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните токен.
2. Threaded Mode не требуется; его можно оставить выключенным.
3. Узнайте Telegram ID каждого оператора, например через
   [@userinfobot](https://t.me/userinfobot).
4. Добавьте ID через запятую в `TELEGRAM_ADMIN_IDS`.
5. После запуска каждый оператор должен открыть личный чат с ботом и нажать
   `/start`.

Бота не требуется добавлять в группу или назначать администратором.

## Работа клиента через Telegram

Любой пользователь, чей ID не входит в `TELEGRAM_ADMIN_IDS`, может открыть
личный чат с этим же ботом. Команда `/start` немедленно создаёт тикет, удаляется
из ленты и заменяется закреплённой Rich-карточкой с номером тикета и кнопкой
«Закрыть тикет». Затем бот отправляет ту же цепочку приветствий с теми же
задержками, что настроены для веб-чата. Ответы поддержки доставляются обычными
Telegram-сообщениями, а Rich-карточка используется только для управления
тикетом.

Кнопка оператора «Отправить кнопку закрытия» удаляет прежнюю управляющую
карточку, отправляет новую и закрепляет её. При закрытии клиентом, оператором
или системой бот удаляет сообщения текущего тикета и оставляет одну свежую
Rich-карточку с причиной закрытия и кнопкой «Создать новый тикет».

- `/start` — сразу создать тикет;
- `/new` — создать новый тикет, если открытого ещё нет;
- `/status` — показать управляющую карточку тикета;
- `/close` — закрыть тикет.

Канал, файлы, обратная доставка, тексты Rich-карточек, причины закрытия и
подписи клиентских кнопок настраиваются в разделе «Управление и состояние → Telegram».
Сама цепочка приветствий едина для сайта и Telegram и редактируется в карточке
«Приветствия и ожидание».
У операторов остаётся отдельный набор команд и кнопка Mini App, поэтому
клиентам операторская админка в меню бота не показывается.

В карточке Telegram-тикета видны ID, username, имя, фамилия, язык и chat ID.
Там же есть действия «Написать лично», «Открыть профиль» и «Копировать ID».

## Быстрый старт

Требования: VPS с Ubuntu/Debian и публичным IPv4, домен с A-записью на этот
IPv4, свободные порты 80 и 443.

```bash
scp -r support_chat root@<IP>:/root/
ssh root@<IP>
cd /root/support_chat
sudo bash setup.sh
```

Скрипт запросит домен, токен бота, Telegram ID операторов и токен админки,
после чего установит Docker и Caddy, настроит HTTPS и запустит приложение.

## Работа оператора

У каждого обращения одна Rich-карточка в основном чате бота. В ней показаны
последние сообщения и доступны «Ответить / отправить файл», «Вложения»,
«Закрыть обращение» и ссылка на полную историю в Workspace.

- Новое сообщение клиента пересоздаёт ту же карточку с уведомлением; прежняя
  удаляется. Быстрые серии сообщений объединяются с интервалом 3 секунды,
  отложенное уведомление сохраняется в базе. Ответы оператора обновляют
  карточку без звука. Новые отдельные темы и дубли входящих не создаются.
- Если ответ ещё не дан, стандартный механизм напоминаний пересоздаёт эту же
  карточку со звуком. По умолчанию первое напоминание через 3 минуты, повтор
  через 5 минут; учитываются рабочие часы и настройки Telegram в админке.
- «Ответить / отправить файл» открывает одну временную подсказку Telegram Reply.
  Напишите ответ или приложите фото, альбом, видео, аудио, голосовое либо
  документ. Можно использовать обычный Reply прямо на карточку. Адресат
  закреплён в базе; простое сообщение без выбранного обращения не отправится
  случайному клиенту. Клиент получает обычное сообщение без цитирования.
- Входящие вложения перечислены в Rich-истории. Кнопка «Вложения» открывает
  последние 10 файлов; выбранный файл приходит как временный предпросмотр.
  Его можно убрать кнопкой; новые предпросмотры заменяют прежние.
- После сохранения ответа в Workspace сообщение оператора, временные подсказки
  и предпросмотры сразу удаляются из Telegram. Это не отменяет доставку:
  текст и файлы остаются в базе и очереди до получения клиентом. При сбое
  удаления работает отдельная сохранённая очередь.
- Вверху карточки веб-обращения показан индикатор «🟢 Клиент в чате» или
  «🔴 Клиент не в чате». Учитываются только видимые вкладки: heartbeat каждые
  15 секунд, потеря связи сбрасывает статус через 35–45 секунд. Несколько
  вкладок учитываются совместно. Изменения обновляют карточку тихо, без
  пересоздания и новых уведомлений.
- Счётчик «Ещё не получено клиентом» учитывает все ответы без подтверждения
  веб-чата. После подтверждения показывается «Все ответы получены клиентом».
  Это получение данных браузером, а не доказательство прочтения человеком.
  Для Telegram-клиента отдельно показаны очередь отправки и ошибки доставки;
  его онлайн-статус и прочтение не выдумываются.
- Закрытие клиентом, оператором, веб-админкой или системой удаляет карточку и
  все известные боту сообщения этого обращения, включая неотвеченные
  вложения и остатки старой схемы. Ошибки удаления сохраняются и повторяются
  после перезапуска. История и файлы в Workspace не удаляются.

При одном операторе работает автоматическое назначение; при нескольких —
атомарная кнопка взятия обращения. Ответы в закрытые и чужие обращения
блокируются. Команды `/start`, `/queue`, `/waiting`, `/open`, `/closed`,
`/system`, `/admin` и Mini App продолжают работать. Панель и списки обновляются
на месте; они не заменяют карточки других клиентов.

Telegram ограничивает удаление обычных сообщений 48 часами и не позволяет
боту получить произвольную историю чата. Удаляются все известные сообщения,
которые API ещё разрешает удалить; старые и неизвестные сообщения могут
остаться. Активные карточки тихо обновляются не реже раза в сутки, чтобы их
можно было удалить при закрытии. Счётчики ожидающей и запрещённой очистки
доступны в `telegram.dialogs` защищённого health endpoint.

При обновлении существующие обращения переходят в основной чат, а прежние
темы, напоминания и дубли удаляются из сохранённой очереди. Для отката только
операторского интерфейса существует `TELEGRAM_OPERATOR_LAYOUT=topics`;
обычный режим — `dialog` (по умолчанию). Не запускайте два экземпляра бота.

## Skill для доработки Telegram-поддержки

[`skills/kv9ru-telegram-support/SKILL.md`](skills/kv9ru-telegram-support/SKILL.md)
описывает текущую модель Rich-диалогов, меню, доставки, присутствия и очистки.
Локальная копия устанавливается в каталог skills Codex под именем
`kv9ru-telegram-support`; её можно вызвать как `$kv9ru-telegram-support`.
Команда `/start` заново выдаёт главную панель, даже если её вручную удалили;
`/admin` и `/queue` обновляют существующую или восстанавливают отсутствующую.
Стартовая панель использует кнопки внутри Rich:
новые обращения, мои диалоги и ожидающие ответа. Архив, система и очистка
находятся в сервисном разделе; при недоступности Rich-блоков остаётся обычная
inline-клавиатура с теми же действиями.
Панель и открытый список обновляются тихо каждые 15 секунд, сохраняя раздел и
страницу. Кнопка ручного обновления не нужна. На главной видна краткая сводка
сервера; в «Системе и обслуживании» — CPU (доля занятого времени между замерами),
память Linux с учётом MemAvailable, свободное место на диске данных, uptime,
версия и очередь доставки. Это показатели хоста, а не одного контейнера.
Подтверждение очистки приостанавливает обновления на минуту. Все операторские
списки, диалоги, вложения и подтверждения используют кнопки внутри Rich.
Открытый список вложений сохраняется при обновлении присутствия; кнопка ответа
у файла привязана именно к нему. Если Telegram отвергает Rich-медиа, файл
отправляется стандартным способом с обычными inline-действиями.

Кнопка оператора «Закрыть обращение» отправляет клиенту предложение завершить
диалог и предупреждение об автоматическом закрытии через 5 минут. Обращение
остаётся открытым: клиент может закрыть его сразу, написать новое сообщение
или выбрать «Продолжить» в Telegram. Любое сохранённое сообщение клиента,
включая вложения, отменяет этот срок. Повторное нажатие оператором не продлевает
его и не дублирует предложение. Срок хранится в SQLite и проверяется каждые
5 секунд независимо от общего таймера неактивности. После истечения срока
клиент получает причину закрытия, а операторская карточка очищается обычным
способом. Команда оператора `/close` остаётся принудительным закрытием.

## Переменные окружения

`setup.sh` создаёт `.env` автоматически. После ручного изменения выполните
`sudo bash update.sh`.

| Переменная | Описание | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота | обязательно |
| `TELEGRAM_OPERATOR_LAYOUT` | `dialog` или старые `topics` для отката | `dialog` |
| `TELEGRAM_MODE` | `private` или временный `legacy` | `private` |
| `TELEGRAM_ADMIN_IDS` | Разрешённые ID операторов через запятую | обязательно |
| `TELEGRAM_POLL_INTERVAL_MS` | Интервал получения обновлений Telegram, мс | `300` |
| `ADMIN_TOKEN` | Токен входа в `/admin` | обязательно |
| `PUBLIC_URL` | Публичный HTTPS URL проекта | — |
| `TELEGRAM_WEBAPP_URL` | Необязательный URL Mini App вместо `PUBLIC_URL/miniapp` | — |
| `PORT` | Порт приложения | `3001` |
| `DB_PATH` | Путь к SQLite | `/app/data/support.db` |
| `UPLOADS_DIR` | Каталог загруженных файлов | `/app/public/uploads` |
| `BACKUP_DIR` | Хранилище проверенных копий БД и зеркала загрузок | `/app/backups` |
| `CORS_ORIGIN` | Разрешённый origin Socket.IO | `*` |

## Переход с супергруппы

Существующая SQLite-база обновляется автоматически, старые сообщения и тикеты
сохраняются.

1. Сделайте резервную копию базы и загрузок.
2. В `.env` задайте:

   ```env
   TELEGRAM_MODE=private
   TELEGRAM_ADMIN_IDS=123456789,987654321
   ```

3. `TELEGRAM_GROUP_ID` можно удалить: в private-режиме он не используется.
4. Включите Threaded Mode у бота.
5. Выполните `sudo bash update.sh`.
6. Каждый оператор один раз отправляет боту `/start`.
7. Проверьте публичный `/health`: он должен вернуть только `ok` и версию.
   Полная техническая диагностика доступна авторизованному администратору в
   `/api/admin/health` или в админ-панели.

Для аварийного отката можно временно вернуть `TELEGRAM_MODE=legacy` и
`TELEGRAM_GROUP_ID`, однако новые приватные темы при этом использоваться не
будут.

## Управление и диагностика

```bash
# Обновление
sudo bash update.sh

# Логи
docker logs support-chat -f

# Healthcheck
curl -fsS https://your-domain.example/health

# Перезапуск и остановка
docker compose restart
docker compose down
```

Публичный `/health` возвращает только признак готовности и версию развёрнутого
образа. Полная диагностика Telegram, очередей, диска и резервного копирования
доступна только с `X-Admin-Token` через `/api/admin/health` и в админ-панели.

## Работа за CDN

Чат не зависит от обязательной поддержки WebSocket. Сначала браузер пытается
подключить Socket.IO через WebSocket, затем через HTTP long-polling. Если CDN
блокирует оба транспорта, отправка автоматически переключается на обычный
HTTPS endpoint, а новые сообщения синхронизируются через HTTPS каждые две
секунды. Идентификатор сообщения сохраняется между попытками, поэтому fallback
не создаёт дублей.

Для минимальной задержки настройте CDN следующим образом:

- включите WebSocket proxying;
- создайте правило **Bypass cache** для `/api/*` (realtime работает на
  `/api/realtime/*`);
- отключите buffering, HTML/JS rewriting и challenge-страницы для
  `/api/realtime/*`;
- не изменяйте query string параметров `EIO`, `transport`, `sid` и `t`;
- разрешите методы `GET` и `POST` на `/api/*`.

Даже без этих исключений клиентские сообщения продолжат ходить через HTTPS,
но индикатор набора текста и мгновенные события будут заменены резервным
режимом с задержкой до двух секунд.

## Резервные копии и обслуживание

Приложение автоматически создаёт SQLite Online Backup, проверяет копию через
`PRAGMA quick_check`, ротирует старые копии и инкрементально синхронизирует
загруженные файлы в отдельный Docker volume. По умолчанию копия создаётся раз
в сутки, хранится 7 копий базы, а осиротевшие файлы проверяются каждые 6 часов.

Все интервалы, переключатели, сроки хранения, пороги заполнения диска и частота
повторения системных уведомлений настраиваются без перезапуска в разделе
«Управление и состояние → Система».
Живые показатели, ручные действия и все настройки находятся на одной странице
«Управление и состояние»; в Telegram её компактная сводка доступна по `/system`.

Для дополнительной внешней копии можно сохранить отдельный backup volume:

```bash
docker cp support-chat:/app/backups ./backup_$(date +%Y%m%d)
```

`update.sh` сначала собирает свежий образ, затем принудительно пересоздаёт только
`support-chat`, проверяет `/health` и совпадение версии коммита, после чего удаляет
лишь висячие старые образы. База, загрузки и резервные копии хранятся в named volumes
и не затрагиваются. Не используйте `docker compose down -v`, если не хотите удалить
эти данные.
