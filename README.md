# Support Chat

Веб-чат поддержки с операторской консолью прямо в личном чате с Telegram-ботом.
Супергруппа не нужна: каждый тикет открывается оператору как отдельная
приватная тема, а карточки тикетов и сообщения клиента отправляются в формате
Telegram Rich Messages.

## Возможности

- обмен сообщениями в реальном времени через Socket.IO;
- фото и скриншоты, включая HEIC/HEIF, AVIF, DNG и TIFF с iPhone,
  видео, аудио и документы до 50 МБ;
- приватные темы тикетов в личном чате каждого оператора;
- тикеты клиентов через личный чат с тем же ботом, без перехода на сайт;
- очередь тикетов и атомарная кнопка «Взять тикет» для нескольких операторов;
- Rich-карточки со статусом, каналом, Telegram-профилем и кнопками действий;
- Mini App с прямым открытием выбранного тикета;
- защита от дублей, очередь повторной доставки и контроль ошибок;
- реакции Telegram, закрытие, переоткрытие и очистка старых тем;
- автозакрытие тикета и HTTPS через Caddy.

## Подготовка Telegram

1. Создайте бота через [@BotFather](https://t.me/BotFather) и сохраните токен.
2. В настройках этого бота у @BotFather включите **Threaded Mode**.
3. Узнайте Telegram ID каждого оператора, например через
   [@userinfobot](https://t.me/userinfobot).
4. Добавьте ID через запятую в `TELEGRAM_ADMIN_IDS`.
5. После запуска каждый оператор должен открыть личный чат с ботом и нажать
   `/start`.

Бота не требуется добавлять в группу или назначать администратором.

## Работа клиента через Telegram

Любой пользователь, чей ID не входит в `TELEGRAM_ADMIN_IDS`, может написать
этому же боту в личные сообщения. Первое сообщение, фото, видео, аудио или
документ создаёт обычный тикет и сразу уведомляет оператора. Ответ из Telegram
или веб-админки приходит клиенту обратно в тот же чат с ботом.

Первым ответом после создания становится закреплённая карточка с номером
обращения и единственной кнопкой «Закрыть обращение». Затем бот отправляет ту
же цепочку приветствий с теми же задержками, что настроены для веб-чата.
Обычные ответы поддержки приходят без кнопок. Оператор может повторно
закрепить управляющую карточку кнопкой в Telegram-теме или в карточке тикета
веб-админки — новое дублирующее сообщение при этом не создаётся.

- `/start` — открыть поддержку;
- `/new` — создать обращение, если открытого ещё нет;
- `/status` — проверить текущее обращение;
- `/close` — закрыть обращение.

При новом сообщении после закрытия прежний тикет можно автоматически
переоткрывать. Канал, файлы, обратная доставка, тексты приветствия и сообщения
о статусе включаются и настраиваются в разделе «Настройки → Telegram-клиенты».
Сама цепочка приветствий едина для сайта и Telegram и редактируется в карточке
«Приветствия и ожидание».
У операторов остаётся отдельный набор команд и кнопка Mini App, поэтому
клиентам операторская админка в меню бота не показывается.

В карточке Telegram-тикета видны ID, username, имя, фамилия, язык и chat ID.
Там же есть действия «Написать лично», «Открыть профиль» и «Копировать ID».

## Быстрый старт

Требования: VPS с Ubuntu/Debian и публичным IPv4, домен с A-записью на этот
IPv4, свободные порты 80 и 443.

```bash
scp -r support_chat root@<IP>:/root/
ssh root@<IP>
cd /root/support_chat
sudo bash setup.sh
```

Скрипт запросит домен, токен бота, Telegram ID операторов и токен админки,
после чего установит Docker и Caddy, настроит HTTPS и запустит приложение.

## Работа оператора

- `/start` — зарегистрировать оператора и открыть сводку;
- `/queue` — открыть панель оператора;
- `/waiting` — показать новые неназначенные тикеты;
- `/open` — показать открытые тикеты оператора;
- `/closed` — показать закрытые тикеты оператора;
- `/admin` — открыть Mini App админки;
- `/close` — закрыть тикет в его приватной теме;
- `/reopen` — переоткрыть тикет.

Если последнее живое сообщение в открытом тикете отправил клиент, бот присылает оператору
звуковое напоминание через 3 минуты и повторяет его каждые 5 минут до ответа или закрытия
тикета. Интервалы и сам механизм меняются в админке в разделе «Telegram: личный бот».

Панель редактируется на месте и не создаёт новое сообщение при каждом
обновлении. В ней есть разделы «Новые», «Мои открытые» и «Закрытые» с
пагинацией. Кнопка «Поднять тему» перемещает выбранную тему наверх нативного
списка тем Telegram.

Закреплённая rich-карточка служит паспортом тикета: показывает статус, клиента,
оператора и время создания. Сообщения не дублируются в карточке — весь диалог,
файлы и ответы идут обычной лентой внутри приватной темы.

Если зарегистрирован ровно один активный оператор, новые тикеты назначаются
ему автоматически. При нескольких операторах остаётся очередь с атомарной
кнопкой «Взять тикет», поэтому два оператора не смогут забрать один тикет.
Каждый новый тикет отправляет отдельное обычное (не бесшумное) уведомление в
основной чат бота: при автоназначении карточка меняет статус на «В работе», а
без назначения остаётся с кнопкой «Взять тикет». Первый диалог с ботом оператор
всё равно должен начать командой `/start` — Telegram не разрешает боту первым
открывать личный чат.

При закрытии тема закрывается сразу. Если очистка включена, закрытая тема
удаляется через заданное в админке количество часов (по умолчанию — 24).

## Переменные окружения

`setup.sh` создаёт `.env` автоматически. После ручного изменения выполните
`sudo bash update.sh`.

| Переменная | Описание | По умолчанию |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота | обязательно |
| `TELEGRAM_MODE` | `private` или временный `legacy` | `private` |
| `TELEGRAM_ADMIN_IDS` | Разрешённые ID операторов через запятую | обязательно |
| `TELEGRAM_POLL_INTERVAL_MS` | Интервал получения обновлений Telegram, мс | `300` |
| `ADMIN_TOKEN` | Токен входа в `/admin` | обязательно |
| `PUBLIC_URL` | Публичный HTTPS URL проекта | — |
| `TELEGRAM_WEBAPP_URL` | Необязательный URL Mini App вместо `PUBLIC_URL/miniapp` | — |
| `PORT` | Порт приложения | `3001` |
| `DB_PATH` | Путь к SQLite | `/app/data/support.db` |
| `UPLOADS_DIR` | Каталог загруженных файлов | `/app/public/uploads` |
| `BACKUP_DIR` | Хранилище проверенных копий БД и зеркала загрузок | `/app/backups` |
| `CORS_ORIGIN` | Разрешённый origin Socket.IO | `*` |

## Переход с супергруппы

Существующая SQLite-база обновляется автоматически, старые сообщения и тикеты
сохраняются.

1. Сделайте резервную копию базы и загрузок.
2. В `.env` задайте:

   ```env
   TELEGRAM_MODE=private
   TELEGRAM_ADMIN_IDS=123456789,987654321
   ```

3. `TELEGRAM_GROUP_ID` можно удалить: в private-режиме он не используется.
4. Включите Threaded Mode у бота.
5. Выполните `sudo bash update.sh`.
6. Каждый оператор один раз отправляет боту `/start`.
7. Проверьте `/health`: `telegram.mode` должен быть `private`,
   `threadedModeEnabled` — `true`, а `registeredOperators` — не меньше числа
   работающих операторов.

Для аварийного отката можно временно вернуть `TELEGRAM_MODE=legacy` и
`TELEGRAM_GROUP_ID`, однако новые приватные темы при этом использоваться не
будут.

## Управление и диагностика

```bash
# Обновление
git pull
sudo bash update.sh

# Логи
docker logs support-chat -f

# Healthcheck
curl -fsS https://your-domain.example/health

# Перезапуск и остановка
docker compose restart
docker compose down
```

В `/health` Telegram-секция показывает соединение, доступность Rich Messages и
Threaded Mode, количество зарегистрированных операторов, неназначенные тикеты,
открытые тикеты из Telegram, возраст очереди и задержки создания темы,
доставки, закрытия и переоткрытия
(`p50`/`p95` по последним 100 операциям).

## Резервные копии и обслуживание

Приложение автоматически создаёт SQLite Online Backup, проверяет копию через
`PRAGMA quick_check`, ротирует старые копии и инкрементально синхронизирует
загруженные файлы в отдельный Docker volume. По умолчанию копия создаётся раз
в сутки, хранится 7 копий базы, а осиротевшие файлы проверяются каждые 6 часов.

Все интервалы, переключатели, сроки хранения, пороги заполнения диска и частота
повторения системных уведомлений настраиваются без перезапуска в разделе
«Настройки → Надёжность и хранение».
Текущее состояние и ручные действия находятся в разделе «Состояние системы».

Для дополнительной внешней копии можно сохранить отдельный backup volume:

```bash
docker cp support-chat:/app/backups ./backup_$(date +%Y%m%d)
```

`docker compose down` не удаляет данные. Не используйте `docker compose down -v`,
если не хотите удалить базу, загрузки и резервные копии.
