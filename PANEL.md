# Универсальная панель

Панель `/admin` и Telegram Mini App `/miniapp` используют общую оболочку:
обзор, поддержка, устройства, шаблоны и управление. На телефоне навигация
расположена снизу, на компьютере — слева. Состояние системы отделено от
редактирования настроек; поиск раскрывает подходящие группы параметров.

Референс организации интерфейса: IBM Carbon UI Shell
https://carbondesignsystem.com/components/UI-shell-left-panel/usage/
Цвета, формы и компоненты реализованы локально без внешних шрифтов и UI CDN.

## Добавление инструмента

1. Зарегистрировать раздел в `public/js/admin-shell.js`.
2. Добавить контейнер в `public/admin.html` и обработку раздела в `setView`
   (`public/js/admin.js`). Изолировать CSS инструмента внутри его контейнера.
3. Проверять права на сервере для каждого API и действия; скрытие кнопки
   само по себе не является защитой. Не передавать сервисные ключи клиенту.
4. Если инструмент работает отдельным процессом, подключить его через
   серверный API панели, как `src/frp-proxy.js`. Сохранить независимый запуск.
5. Проверить desktop, tablet, mobile, клавиатуру и Telegram safe areas.

FRP продолжает работать отдельным сервисом. Встроенная панель использует
сессию администратора; отдельная панель использует свой FRP_ADMIN_TOKEN.
Конфигурация устройств без token сохраняет совместимость в соответствующем
режиме. HTTP-туннель открывается через HTTP: смена ссылки на HTTPS не добавляет
TLS на устройство. Настройка диапазонов FRP не заменяет правила firewall хоста.

## Проверка изменений

- `npm run check` и `npm test` в корне.
- `npm run check` и `npm test` в `tools/frp`.
- `npm audit` и `git diff --check`.
- Локально: вход, переписка клиента и оператора, сохранение настроек,
  навигация, группировка устройств, выход; тестовые сообщения не отправлять
  в рабочие клиентские обращения.
- После выкладки: health, доступность ресурсов, отказ без авторизации,
  разрешённый доступ к FRP и состояние обоих независимых сервисов.

Физические Safari/macOS/iOS и Telegram WebView требуют отдельного тестирования
на соответствующих устройствах; эмуляция размеров окна не заменяет их.

## Прочтение и удаление сообщений

«Прочитать всё» в разделе поддержки отмечает сообщения во всех обращениях,
включая закрытые. Обращения не закрываются и сообщения не удаляются.
Состояние хранится на каждом сообщении: новое сообщение, поступившее в ту же
секунду после нажатия, остаётся непрочитанным. Миграция сохраняет прежние отметки.

Исходный текст ответа оператора в Telegram удаляется после подтверждения доставки
клиентскому каналу. Истёкший срок удаления (48 часов) и постоянный отказ Telegram
останавливают задание очистки: `blocked_at` и `last_error` сохраняют причину в базе.
Сетевые ошибки продолжают повторяться. Остановка очистки не удаляет переписку из
базы и не означает, что Telegram удалил исходное сообщение.

## Аудио

Раздел доступен администраторам с правом управления настройками, в том числе
через существующую авторизацию Mini App. Сервис работает отдельно от чата и FRP.
Серверные VOICE_SERVICE_URL и VOICE_SERVICE_TOKEN соединяют его с общей панелью.
Инструкция: [tools/voice/README.md](tools/voice/README.md).

## Центр управления

Обзор показывает поддержку, realtime, Telegram, диск и резервные копии; менеджерам
также доступны FRP, аудиобот, Lampac, TorrServer и регистрации Lampa. Каждый источник
опрашивается независимо с таймаутом 8 секунд, обновление каждые 15 секунд только на
активной вкладке обзора. Ошибка источника показывает отсутствие свежих данных.
Очередь аудиобота рассчитана по последним 30 заданиям, а не по всей истории.
Данные прошлой сессии сбрасываются; оператор не запрашивает сервисы менеджера.
